# 真機實驗設計：Tuna-17（Quantum Inspire / QuTech）

> 決策（2026-09-21）：真機平台定為 **Quantum Inspire 的 Tuna-17**。
> 理由見 §1；Quafu 的 ScQ-P5 已排除（§1.4）。

---

## 一、平台與規格（2026-09-21 實測）

### 1.1 Tuna-17

| 項目 | 值 |
|---|---|
| 平台 | Quantum Inspire（QuTech：TU Delft ＋ TNO） |
| 類型 | **真機**（`is_hardware=True`）、超導 |
| qubit 數 | **17** |
| 耦合圖 | **24 條無向邊**（48 條有向），例如 (0,1)(0,2)(4,1)(4,2)(4,7)(4,8)(5,2)(5,3)(5,8)(5,9)… |
| 閘集 | `cx cz rx ry rz x y z h s sdg t tdg swap cp id delay reset measure` |
| 最大 shots | 131072 |
| 取得方式 | 免費註冊 ＋ `qi login`（裝置授權流程） |

**我們的 ansatz 只需要 `ry / rz / cx`，全部原生支援** —— 不需要任何閘分解。

### 1.2 為什麼 17 個 qubit 對我們有意義

模擬端的容量網格掃到 **n = 3…10**。Tuna-17 的 17 個 qubit 足以**完整容納**整個掃描，
所以「模擬端的容量曲線能不能轉移到真機」是一個可以直接做的實驗，不必縮減設計。

### 1.3 已驗證的第一個資料點

`qbn5_book`（5 logical qubit，轉譯後深度 9、21 閘）在 Tuna-17 上 8192 shots：
`max|dP| = 1.279e-01`，約為取樣雜訊（1.10e-02）的 **11.6 倍**，
六個主要態全部掉機率、χ² = 210282 / df = 31。
證據：`runs/qi_qbn5_book_Tuna-17_8192_20260921-032832.json`。
**這就是真機的雜訊底**，後面所有真機宣稱都必須先跨過它。

### 1.4 為什麼不是 Quafu ScQ-P5

2026-09-20 01:54 送出（taskid `8E04C01019B694A7`），約 25 小時後仍是 `In Queue`，
且 P5 佇列在 11.5 小時內由 733 → **735**（不減反增）。等待不是策略。

## 二、真機只能做推論 —— 這決定了整個架構

真機不能反傳。所以：

```
模擬端訓練（既有管線 s16/s17）          真機端只做前向
        │                                      │
        │  匯出訓練好的角度 θ                  │
        ▼                                      ▼
   q01 IR ──► OpenQASM 2.0 ──► QI transpile ──► Tuna-17 ──► counts
                                                              │
                          與模擬端精確機率對帳 ◄──────────────┘
```

⚠️ **必要前置**：`s16` 目前**沒有儲存訓練好的參數**（`rows` 只有指標，
也沒有任何 `torch.save`／`np.save`）。沒有角度就無法在真機上重現同一個分類器。
→ 必須先在訓練腳本加上參數匯出（見 §5）。

## 三、三個子實驗與事前決策規則

規則先寫定，負面結果才算結果，而不是事後重新詮釋。

### 實驗 A：深度轉移（n = 5 固定）

| 項目 | 內容 |
|---|---|
| 電路 | n = 5、**L ∈ {1, 2, 4}**，共 3 條（⚠️ 2026-09-21 修訂，見 §3.1） |
| 來源 | 以固定種子重訓、匯出角度；**真機不重新訓練** |
| shots | 8192 |
| 量測 | 由 counts 算 accuracy / ECE / NLL，與模擬端精確值比 |
| **決策規則** | 若真機準確率落在模擬端 95% 信賴區間內 → 深度效益轉移；
|  | 若隨 L 單調劣化 → 論文「深度是主要驅動力」是模擬產物，必須改寫 |

#### 3.1 ★ 深度範圍修訂（2026-09-21，由實測的轉譯深度決定）

原訂 L ∈ {2,4,6,8}。實測 Tuna-17 的轉譯結果後收窄為 L ∈ {1,2,4}：

| 電路 | 原始深度 | 轉譯後深度 | 閘數 | SWAP |
|---|---|---|---|---|
| `qbn5_book`（固定電路） | 4 | **9** | 21 | 0 |
| n=5, L=2 | 12 | **19** | 41 | 4 |
| n=5, L=8 | 50 | **75–101** | 143 | **18–32** |

L=8 需要 40 個 CX ＋ 18~32 個 SWAP（SWAP = 3 個 CX）＝ 等效約 **94 個雙閘**。
而深度 9 的固定電路就已經量到 max abs(dP) = 0.128。**L=8 會被雜訊完全吃掉。**
這不是妥協，是量測結果。

### 實驗 B：qubit 數轉移（低深度固定）

| 項目 | 內容 |
|---|---|
| 電路 | L = 8、n ∈ {3, 5, 8, 10}，共 4 條 |
| 為什麼是這四個 | n=3 是結構性下限、n=5 是本專案主電路、n=8/10 測主張的尾端 |
| **決策規則** | 若真機重現「峰值自 n=4 起單調下降」的排序 → 主張轉移；
|  | 若真機單調上升或無序 → 模擬端的主張是模擬產物，必須收窄 |

### 實驗 C：雜訊底與深度關係（已完成第一點，可延伸）

同一條電路在不同深度下量 `max|dP|`，擬合出「每個 CX 的等效錯誤率」。
這給出一個可引用的硬體數字，也是 A/B 兩實驗的解釋基礎。

## 四、協定（全部固定，不得事後調整）

| 項目 | 固定值 | 理由 |
|---|---|---|
| shots | **8192** | 取樣雜訊 1.1e-02，遠小於真機雜訊底 1.28e-01 |
| transpiler | `transpile(qc, backend, optimization_level=1, seed_transpiler=0)` | 可重現 |
| 邏輯→實體對映 | **每次記錄下來** | 不同對映的錯誤率不同，不記錄就無法解釋離群 |
| 讀出錯誤緩解 | 先跑校正電路估混淆矩陣，再反矩陣 | real-hardware 論文標準配備 |
| 執行順序 | 同一批內交錯（不要全部 A 再全部 B） | 避免漂移被誤認為系統效應 |
| 位元序 | `idx = int(bits[::-1], 2)`，並**逐次以 top-k 吻合度驗證** | Quafu 的陷阱（§hardware README 7.4） |

**位元序的判準不是 `max|dP|`。** 實測發現：偏差由主要態主導時，
反轉與不反轉的 `max|dP|` 會相同（都是 0.1279）。真正的判準是 **top-k 狀態是否吻合**。

## 七、已知限制（必須寫進論文）

1. **真機只做推論，訓練全在模擬端。** 真機結果回答的是「訓練好的模型推論時是否轉移」，
   不是「能不能在真機上訓練」。
2. **Tuna-5（5 qubit，與主電路同尺寸）當下 OFFLINE**，所以 5 個邏輯 qubit 是對映到
   Tuna-17 的 17 個實體 qubit 中的 5 個。**這是不同的硬體**，不能宣稱「在 5 qubit 晶片上驗證」。
3. **不主張量子優勢。** 17 qubit 的狀態向量 2^17 仍完全可古典模擬。
4. 真機的每次執行都是獨立抽樣，**無法取回狀態向量**；所有指標只能由 counts 估計。
