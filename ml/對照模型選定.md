# 對照模型的選定（依使用者決定）

> 本檔記錄**最終決定**。詳細的逐欄核實見 `對照模型規格.md`（MD1 產出，365 行）。
> 本檔所有 `bekko` 規格由 HF API 直接抓取，非二手引用。

---

## 一、為什麼要換掉原候選

| 原候選 | 處置 | 理由 |
|---|---|---|
| `sentence-transformers/LaBSE` | ❌ **移除** | 1.75 GiB，超出可部署範圍；且它只是 `M2V` 的老師，已被 `bge-m3` 取代為錨點 |
| `BAAI/bge-m3` | 🔸 **降為上限錨點** | 2.11 GiB，不是對手而是「potion 的老師」，用來量「學生離老師多遠」 |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | ❌ **移除** | MD1 發現它**實務只吃 128 token**（config 寫 512，但 `sentence_bert_config.json` 與模型卡皆為 128），引入無法控制的變數 |
| **新增** | ✅ `hotchpotch/bekko-embedding-v1-a25m` | **能力相當、可部署、MIT、有 int8** |

**使用者的要求**：「最好是在同一個量級或者能力比較好」——`bekko` 正好符合。

## 二、新增的主要對手：`bekko-embedding-v1-a25m`

**來源**：HF API `https://huggingface.co/api/models/hotchpotch/bekko-embedding-v1-a25m`（2026-09-16 抓取）

| 項目 | 值 |
|---|---|
| **Active 參數量** | **24,930,432**（≈ 24.9M） |
| **總參數量** | 123,234,432（絕大多數是詞表；推論成本只算 active） |
| 架構 | mmBERT（ModernBERT 式），13 層，hidden 384 |
| **嵌入維度** | **384**，Matryoshka 可截到 **256 / 128 / 64** |
| 維度 256 的品質損失 | **−1.35%**（HAKARI overall 0.570 → 0.562） |
| max sequence length | **8192 tokens** |
| Pooling | Mean pooling |
| 語言 | 100+（繼承自 mmBERT） |
| 授權 | **MIT** |
| 下載 / likes | 21,237 / 23 |
| 論文 | arXiv:2607.25180（*Bekko Embedding: Parameter-Efficient Multilingual Retrieval with Ultra-Compact Encoders*） |
| **ONNX int8 版** | 主檔由 ~470 MiB 降到 **~190 MiB** |

**效能（模型卡自述，MMTEB Multilingual v2，131 任務）**：

| 模型 | Active 參數 | Mean | Retrieval | STS |
|---|---|---|---|---|
| **bekko-a25m** | **24.9M** | **58.3** | **57.5** | **73.4** |
| multilingual-e5-small | 21.6M | 56.4 | 50.9 | 71.7 |
| gte-multilingual-base | 113.3M | 58.3 | 57.2 | 72.9 |
| multilingual-e5-large | 303.9M | 58.6 | 53.7 | 73.3 |
| BGE-M3 | 311.8M | 59.6 | 54.6 | 74.1 |

→ **它以 1/4.5 的參數量打平 `gte-multilingual-base`，Retrieval 勝過 `e5-large` 與 `BGE-M3`。**

**CPU 吞吐**（Ryzen 9 7950X + OpenVINO）：**134 docs/s**（對照 multilingual-e5-large 的 21 docs/s）。

!!! danger "欄位陷阱：`bekko` 的分數不可與 `potion` 直接相減"
    `bekko` 用 **MMTEB Multilingual v2**（131 任務），`potion` 用**另一套表**（Mean (Task) 47.31）。
    **兩者不可直接比較。** 唯一誠實的做法是**我們自己在同一套 MTEB 子集上重跑兩者**。
    這正是為什麼本專案必須自己做評測，而不是引用別人的數字。

## 三、最終對手表

| 角色 | 模型 | 規格 | 為什麼 |
|---|---|---|---|
| **基準線** | `minishlab/potion-multilingual-128M` | 128.09M 參數 / 256 維 / 488.6 MiB / Mean(Task) 47.31 | 我們的前端 |
| **主要對手** | `hotchpotch/bekko-embedding-v1-a25m` | 24.9M active / 384→256 維 / 190 MiB (int8) / MMTEB Mean 58.3 | **能力相當且可部署** |
| **同架構消融** | `minishlab/M2V_multilingual_output` | 128.27M / 256 維 / 489.3 MiB / Mean(Task) 42.13 | **只換老師**（LaBSE → bge-m3），證明「老師更強 = 學生更好」 |
| **參數量下限** | `minishlab/potion-base-32M` | 123.2 MiB（**唯一位於 100–200 MB 區間者**） | 規模對照，但**英文單語** |
| **上限錨點** | `BAAI/bge-m3` | 2.11 GiB | potion 的老師，量「學生離老師多遠」 |
| **zh-TW 參考點** | `intfloat/multilingual-e5-small` | 21.6M active | 其 model-index 內**有 `MassiveIntentClassification (zh-TW)` 的實測** → 找繁體中文資料集的線索 |

### ★ 同架構消融是這張表最有價值的一格

`potion-multilingual-128M` 與 `M2V_multilingual_output` 的差異**只有兩項**：

| 面向 | M2V | potion |
|---|---|---|
| 老師 | LaBSE | **bge-m3** |
| 訓練法 | 論文未載 | **Tokenlearn**（C4 101 語言 200 萬句） |
| 維度 | 256 | 256（**相同**） |
| 參數量 | 128.27M | 128.09M（**差 0.14%**） |
| 檔案 | 489.3 MiB | 488.6 MiB（**幾乎相同**） |

**其餘全部相同。** 這是比 Wang et al. 的「貝氏 vs 確定性卷積」更乾淨的單一變因設計——因為兩者的**維度、參數量、檔案大小、架構全部對齊**，只換了老師與訓練法。

## 四、「100–200 MB 戰場」的更正

MD1 用數字證明此設定不成立：

> 七個模型中**只有 `potion-base-32M`（123.2 MiB）**落在該區間，
> 而**基準線自己 488.6 MiB、超出上限 2.4 倍**——**基準線站在戰場外**。

**替代定義**（採用使用者的說法「同一量級或能力相當」）：

| 定義 | 內容 | 誰符合 |
|---|---|---|
| **主定義 A：單機 CPU 可部署** | 能在一般筆電 CPU 上跑 | potion-multilingual、M2V、potion-base-32M、bekko-a25m（int8） |
| **輔助定義 B：能力相當** | 在 MMTEB 上的 Mean 差距 ≤ 3 分 | bekko-a25m（58.3 vs potion 的對應欄位，需自行重跑確認） |

## 五、待核實（不可自行填補）

1. `bekko-a25m` 在 **MMTEB Multilingual v2** 之外的欄位分數（模型卡只給 131 任務那套）
2. `bekko-a25m` 的 **zh-TW 實測表現**（卡片說「100+ 語言，覆蓋不均，部署前請在自己的語言與領域上評估」）
3. `potion` 與 `M2V` 的 **zh-TW 實測表現**（兩者的語言標籤都只有 `zh`，未宣告 zh-TW）
4. `bge-m3` 是否涵蓋 zh-TW（卡片只寫 "more than 100 working languages"）
5. 三者（potion / M2V / bekko）在**同一套 MTEB 子集**上的分數——**這是我們要自己跑的**

**第 5 項是本專案的核心工作量**，也是「實務驗證」與「引用別人數字」的分界線。
