# 可部署嵌入模型對手表（已核實規格）

> 本表只記錄**能追到來源 URL 的數字**。查不到的欄位一律寫 `TODO(核實)`，不做推測填空。

## 一、調查方法

全部使用 Hugging Face 的第一手端點，未經任何二手彙整或搜尋引擎。實際抓取的 URL 型態如下：

| 用途 | URL 樣式 | 說明 |
|---|---|---|
| 模型 metadata | `https://huggingface.co/api/models/<owner>/<name>` | 取 `downloads`、`likes`、`tags`、`safetensors.total`、`cardData` |
| 權重檔大小 | `https://huggingface.co/api/models/<owner>/<name>?blobs=true` | **權威來源**：`siblings[].size` 為各檔案實際 bytes |
| 模型設定 | `https://huggingface.co/<owner>/<name>/raw/main/config.json` | 取 `hidden_size` ／ `hidden_dim` ／ `max_position_embeddings` |
| 模型卡 | `https://huggingface.co/<owner>/<name>/raw/main/README.md` | 取語言清單、授權、蒸餾敘述、MTEB 結果表 |
| 實際切斷長度 | `https://huggingface.co/<owner>/<name>/raw/main/sentence_bert_config.json` | Sentence-Transformers 的 `max_seq_length`（與 config.json 不同，見 §3.2 註記） |

七個模型在上述五類端點全部成功回應，**核實成功率 7/7**。

### 關鍵方法學修正（必讀）

1. **`?blobs=true` 是檔案大小的唯一權威來源。**
   不帶此參數時，API 只回傳 `rfilename`，完全不回傳大小。專案內若有人用 `usedStorage` 當「模型大小」，那會嚴重高估：例如 `potion-multilingual-128M` 的 `usedStorage` 是 1,077,973,636 bytes，但那包含 ONNX 副本與 tokenizer，**不是下載一個模型所需的大小**。

2. **模型卡 frontmatter 的語言清單必須扣除表頭那一行 `multilingual`。**
   它是布林標記不是語言。本文所有「語言數」皆已扣除，且與模型卡本文宣稱的數字交互驗證。

3. **`safetensors.total` 並非每個模型都有。**
   `BAAI/bge-m3` 只提供 `pytorch_model.bin`，HF 無法解析其參數量，故該欄以標註方式處理（見 §3.3）。

4. 未使用 `platform_search` 與 `search_arxiv`（本專案已證實不可靠）。

5. **「無限長度」要用兩份檔案交叉確認，不能只信 `config.json`。**
   `config.json` 的 `seq_length: 1000000` 只是 model2vec 的哨兵值。真正的上限在 tokenizer：
   - `potion-multilingual-128M` 的 `tokenizer_config.json` 為 `model_max_length: 1000000000000000019884624838656`（即「無上限」哨兵，該數字是 float 溢位後的殘值）→ **確實無上限**。
   - `M2V_multilingual_output` 與 `potion-base-32M` 為 `model_max_length: 1000000` → 名義上限 100 萬 token。
   三者對本專案的長文件情境都是「不受限」，但寫進論文時應引用**這一格**，不要只引 `config.json`。

## 三、分組討論

### 3.1 同架構對手（model2vec 家族）

這三個模型同屬 `library_name: model2vec`、`architectures: ["StaticModel"]`，推論方式完全一致：**查表取 token 向量 → 取平均**，沒有注意力層，因此 CPU 上是常數級成本。

**（1）`potion-multilingual-128M` — 我們的基準線**

- 模型卡原文：「a distilled version of the `BAAI/bge-m3` Sentence Transformer」、「trained on 101 languages」、「produces **256 dimensional** embeddings, and has a theoretically unlimited context length since embeddings are static (pre-computed)」。
- `config.json` 證實：`hidden_dim: 256`、`seq_length: 1000000`、`normalize: true`、`tokenizer_name: "BAAI/bge-m3"`。
- 參數量 128,090,368，反推詞表：128,090,368 ÷ 256 = 500,353 → 扣除 bias 後詞表 **500,002**，與 bge-m3 的 `vocab_size: 250002`（XLM-R sentencepiece，每個 token 算前綴空白故翻倍）相符。**這個數字必須記住**：512 MB 的權重裡有 99.99% 是詞表，不是「模型變聰明」。

**（2）`M2V_multilingual_output` — 最直接的同架構對手**

- 模型卡原文：「a distilled version of the `sentence-transformers/LaBSE` Sentence Transformer」。
- `config.json`：`tokenizer_name: "sentence-transformers/LaBSE"`、`apply_pca: 256`、`apply_zipf: true`、`normalize: false`（**注意：與 potion 相反，不做 L2 正規化**）。
- ⚠️ **config.json 沒有 `hidden_dim` 欄位**。維度 256 必須由 `apply_pca: 256` 加上參數量反推：128,269,824 ÷ 256 = 501,054 → 扣 bias 501,053 → LaBSE 詞表 501,153（bias 501,053 + 100 未使用）。三方一致，維度 256 確認。
- **名稱陷阱**：`M2V_multilingual_output` 的數字「128M」不在名字裡，但它與 potion-multilingual-128M 的參數量幾乎相同（128.27M vs 128.09M，差 0.14%）。**不要因為名字沒有數字就以為它比較小。**
- 檔案大小也幾乎一樣（513.08 MB vs 512.36 MB），**部署成本差別可忽略**；差別純粹在品質（Mean (Task) 42.13 vs 47.31）與正規化行為。

**（3）`potion-base-32M` — 大小／品質對照點**

- 模型卡原文：蒸餾自 `baai/bge-base-en-v1.5`，並在 Tokenlearn 訓練後做「post-training re-regularization：frequency weighting → PCA → SIF weighting」。
- `config.json`：`apply_pca: 512`、`hidden_dim: 512`、`normalize: true`、`tokenizer_name: "baai/bge-base-en-v1.5"`。
- **英文單語**，不是多語言。`cardData` 完全沒有 `language` 欄位，tags 也沒有任何語言碼。
- 128,090,368 → 32,302,592，維度 256 → 512：**縮到 1/4 參數量、放大 2 倍維度，換來的是英文 MTEB 的 `Avg (MTEB)` 52.13（potion-multilingual 是 `Mean (Task)` 47.31）**。
- ⚠️ **這兩個分數不能相減**。欄位名不同（見 §四第 2 點）。

**同架構家族的關鍵不對稱**：三個 model2vec 模型的權重檔全部 ≥ 123 MB，其中兩個 488 MB 級。**「model2vec 就是小模型」在本家族的 128M 級成員上並不成立。**

### 3.2 同參數量級的 Transformer 對手

**（4）`paraphrase-multilingual-MiniLM-L12-v2`**

- 參數量 117,654,272，與 potion-multilingual-128M（128,090,368）相差 **8.9%**，**這是全表中與基準線參數量最接近的模型**。
- 維度 384（`hidden_size`），12 層。
- **長度雙重陷阱**：`config.json` 的 `max_position_embeddings` 是 **512**，但 `sentence_bert_config.json` 寫 `{"max_seq_length": 128, "do_lower_case": false}`，模型卡 Usage 章節的 `Full Model Architecture` 也印出 `max_seq_length': 128`。**實務上這個模型只吃 128 個 token**，是 potion 之外全表最短的。任何長文件檢索的實驗設計都必須先處理這件事。
- **zh-TW 是它唯一的加分項**：`language` 清單 49 項裡**沒有 `zh`**（推測原文清單把中文歸在 `zh-cn`／`zh-tw` 而未列 `zh`），但 `cardData.language_bcp47` 明確列出 `["fr-ca", "pt-br", "zh-cn", "zh-tw"]`。這是全表唯一在 metadata 層級**明確宣告 zh-TW** 的模型。
- 授權 Apache-2.0，下載 45,668,102、likes 1,404 —— **全表下載量最高**。
- **無任何 MTEB 分數**：`model-index` 為 `null`，模型卡全文沒有結果表。要分數只能去 MTEB leaderboard 現場查，故列 `TODO(核實)`。

**（5）`intfloat/multilingual-e5-small`**

- 參數量 117,653,760 —— 與 MiniLM-L12-v2 的 117,654,272 **只差 512**（那 512 是 `I64` 型別的 buffer，見 `safetensors.parameters: {"I64": 512, "F32": 117653760}`）。**兩者實質同構、同量級**：都是 12 層、`hidden_size: 384`、`vocab_size: 250037` 的 XLM-R 詞表 BERT。
- `max_position_embeddings: 512`，且 `sentence_bert_config.json` 也是 `max_seq_length: 512`，**沒有 MiniLM 那個 128 的縮減**。
- 語言數 **93**（frontmatter 94 條扣掉 `multilingual`），與論文標題的「Multilingual E5」相符但**不是 100**。
- **MTEB 分數是本表最麻煩的一格**：模型卡的 `model-index` 塞了 18,309 行 YAML、836 筆 task 條目、525 個 `main_score`，逐任務分數齊全，但**沒有任何聚合的 Mean(Task)／Mean(TaskType)**。硬規則 4 要求標清楚欄位，而「逐任務分數」不是一個可對比的欄位，故列 `TODO(核實)`，不可自行平均。
- **zh-TW 的細節**：`language` 清單沒有 `zh-TW`，但 `model-index` 內確實有 `MTEB MassiveIntentClassification (zh-TW)` 與 `(zh-CN)` 兩個 config 的評測結果。**「未宣告」不等於「未評測」**，這點與 MiniLM 相反（MiniLM 是宣告了但沒分數）。

**（6）為什麼這兩個是「實務上真的會部署」的代表**

下載數是客觀證據：45.67M 與 12.31M。它們是 Sentence-Transformers 生態的預設選擇，ONNX／OpenVINO／TensorFlow 格式齊備（見 §2.2），有官方 int8 量化。**與 potion 的對照價值在於「同樣吃 0.5 GB 磁碟，多換到多少品質」**，而不是「同樣 100–200 MB」。

### 3.3 老師級模型（上限對照）

**（7）`BAAI/bge-m3` — potion 的直接老師**

- 模型卡原文：「unified fine-tuning (dense, sparse, and colbert) from bge-m3-unsupervised」，並註明「Multi-Linguality: It can support **more than 100 working languages**」（卡片原文措辭，未給精確數字）。
- `config.json`：`hidden_size: 1024`、`max_position_embeddings: 8194`（模型卡 Specs 表寫序列長度 **8192**）、`num_hidden_layers: 24`、`intermediate_size: 4096`、`vocab_size: 250002`、`model_type: xlm-roberta`。
- **參數量欄位為 `TODO(核實)` 的理由（必讀）**：`https://huggingface.co/api/models/BAAI/bge-m3` 回傳的 `siblings` **不含 `model.safetensors`**，只有 `pytorch_model.bin`（2,271,145,830 B）與拆分式 `onnx/model.onnx` + `onnx/model.onnx_data`。HF 的 `safetensors.total` 欄位因此缺席。**不可因此推論它沒有參數量，只是 HF 沒有可解析的欄位。**
  若要一個權威數字，需改抓 `https://huggingface.co/BAAI/bge-m3/raw/main/model.safetensors.index.json` 或直接讀 `pytorch_model.bin` —— 兩者都超出「只抓 metadata」的界線，故誠實留白。
- 授權 MIT、下載 38,094,575、likes 3,566 —— **likes 全表最高**。
- **MTEB 分數同樣留白**：卡片的 Evaluation 章節是 Miracl／MKQA／MLDR／NarrativeQA 的**圖片**（`imgs/miracl.jpg`、`imgs/mkqa.jpg`、`imgs/long.jpg`、`imgs/nqa.jpg`），沒有任何文字化分數可引用。`TODO(核實)`。
- **它不是被蒸餾出來的老師，它自己用「自我知識蒸餾（Self-knowledge Distillation）」訓練**：卡片原文「combining multiple outputs from different retrieval modes as reward signal」。**「bge-m3 的老師是誰」這個問法本身不成立**，要寫成「bge-m3 是 potion 的老師；bge-m3 自身無外部老師」。

**（8）`sentence-transformers/LaBSE` — M2V 的老師**

- 模型卡原文：「a port of the `LaBSE` model to PyTorch. It can be used to map **109 languages** to a shared vector space.」109 與 frontmatter 反推值（110 − 1）一致。
- `config.json`：`hidden_size: 768`、`max_position_embeddings: 512`、12 層、`vocab_size: 501153`。
- **實務長度是 256，不是 512**：`sentence_bert_config.json` 為 `{"max_seq_length": 256}`，模型卡 `Full Model Architecture` 同樣印 `max_seq_length': 256`。
- 架構上有額外兩層：`(2): Dense(768→768, Tanh)` 與 `(3): Normalize()`。**M2V 蒸餾時把這兩層的行為壓進了靜態向量（`normalize: false`），這是兩者推論不等價的來源之一。**
- 權重 1.75 GiB，**是全表最大**。它同時是 potion 模型卡的對照列（Mean (Task) 52.07），也是 M2V 的來源模型 —— **這個雙重身分讓它成為最重要的單一對照點**。
- 授權 Apache-2.0（不是 MIT，與 Minish Lab 的衍生模型不同，引用時要分開寫）。

## 四、誠實的「同級」定義問題

### 4.1 ★ 「100–200 MB 戰場」這個設定本身是錯的

專案內部文件把對照範圍設定在 **100–200 MB**。核實結果如下：

| 模型 | fp32 主權重 | 是否落在 100–200 MB |
|---|---|---|
| `potion-multilingual-128M`（**我們的基準線**） | **512,361,560 B = 488.6 MiB** | ❌ **超出上限 2.4 倍** |
| `M2V_multilingual_output` | 513,079,384 B = 489.3 MiB | ❌ 超出 |
| `potion-base-32M` | 129,210,456 B = 123.2 MiB | ✅ |
| `paraphrase-multilingual-MiniLM-L12-v2` | 470,641,600 B = 448.8 MiB | ❌ 超出 |
| `intfloat/multilingual-e5-small` | 470,641,600 B = 448.8 MiB | ❌ 超出 |
| `BAAI/bge-m3` | 2,271,145,830 B = 2.11 GiB | ❌ 超出 |
| `sentence-transformers/LaBSE` | 1,883,734,344 B = 1.75 GiB | ❌ 超出 |

**結論：七個模型中只有 `potion-base-32M` 一個落在 100–200 MB，而且它是英文單語、不是多語言。**
「100–200 MB 的多語言嵌入模型對照」這個戰場**在我們自己的基準線上就不成立** —— 基準線自己站在戰場外。

**這個錯誤可能的來源（供除錯用）**：
1. 把模型名字裡的「128M」誤讀成「128 MB」（它是**參數量** 128M，換成 fp32 就是 512 MB）。
2. 把 `usedStorage`（1.08 GB，含 ONNX 副本與 tokenizer）誤讀成下載大小。
3. 把某個量化版本的印象套到 fp32 上。

### 4.2 替代的「同級」定義（建議採用 A 為主張、B 為輔助）

**定義 A：單機 CPU 可部署（single-machine CPU deployable）— 建議作為主定義**

判準：不需要 GPU、單一 process 常駐、記憶體足跡 ≤ 1 GB、無外部服務依賴。

| 模型 | 權重足跡 | 是否同級 | 備註 |
|---|---|---|---|
| `potion-multilingual-128M` | 488.6 MiB | ✅ | 常數時間推論，CPU 首選 |
| `M2V_multilingual_output` | 489.3 MiB | ✅ | 同上 |
| `potion-base-32M` | 123.2 MiB | ✅ | 英文單語，可作下限 |
| `paraphrase-multilingual-MiniLM-L12-v2` | 448.8 MiB fp32／**113.0 MiB int8** | ✅ 有條件 | fp32 可 CPU 跑但慢；int8 才真正輕 |
| `multilingual-e5-small` | 448.8 MiB fp32／**112.9 MiB int8** | ✅ 有條件 | 同上 |
| `BAAI/bge-m3` | 2.11 GiB | ⚠️ 邊緣 | CPU 可跑但延遲不可接受；定位為「上限」而非「同級」 |
| `sentence-transformers/LaBSE` | 1.75 GiB | ⚠️ 邊緣 | 同上 |

**定義 B：參數量同級（parameter-count parity，以 potion-multilingual-128M 為錨，允許 ±30%）**

判準：`safetensors.total` 落在 89.7M ～ 166.5M。

| 模型 | 參數量 | 是否同級 | 與基準線差距 |
|---|---|---|---|
| `potion-multilingual-128M` | 128,090,368 | ✅（錨） | — |
| `M2V_multilingual_output` | 128,269,824 | ✅ | +0.14% |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 117,654,272 | ✅ | −8.15% |
| `intfloat/multilingual-e5-small` | 117,653,760 | ✅ | −8.16% |
| `potion-base-32M` | 32,302,592 | ❌ | −74.8%（差一個數量級） |
| `BAAI/bge-m3` | 無欄位 | ❓ 不可判定 | 見 §3.3 |
| `sentence-transformers/LaBSE` | 470,927,360 | ❌ | +268% |

**定義 C：維度同級（dimension parity）— 不建議**

potion-multilingual 是 **256 維**，M2V 也是 256 維，但 LaBSE 是 768 維、bge-m3 是 1024 維。
**維度與下游客戶端儲存成本直接相關**（1 億筆向量：256 維 fp32 = 102.4 GB，1024 維 = 409.6 GB）。
若專案在意索引成本，應把維度當成「共同的評估維度」而不是「挑對手的條件」。

### 4.3 MTEB 欄位不可互比（硬規則 4 的落實）

本表出現三種**互不相容**的欄位，任何跨欄位相減都是無效比較：

| 欄位名 | 出現於 | 定義 |
|---|---|---|
| `Mean (Task)` | potion-multilingual-128M 卡、LaBSE 卡 | 逐任務分數先平均，再對任務平均 |
| `Mean (TaskType)` | 同上 | 先對任務類型平均，再對類型平均 |
| `Avg (MTEB)` / `Avg (All)` | potion-base-32M 卡 | 另一套英文 MTEB 子集，含 `Sum`／`Pearl`／`WordSim` 等**多語言表沒有的欄位** |

**具體禁止事項**：
- ❌ 不可寫「potion-base-32M（52.13）比 potion-multilingual-128M（47.31）好 4.82 分」。
- ✅ 可寫「potion-base-32M 在其卡片的 `Avg (MTEB)` 欄位為 52.13；potion-multilingual-128M 在其卡片的 `Mean (Task)` 欄位為 47.31；**兩欄位定義不同，不可相減**」。
- ✅ 唯一可直接相減的一組：potion-multilingual-128M 的 `Mean (Task) 47.31` 與 LaBSE 的 `Mean (Task) 52.07`（同卡、同表、同欄位）。
- ⚠️ 同一張表的 `M2V_multilingual_output` `Mean (Task) 42.13` 也可直接比 —— 但**它與 LaBSE 同表，卻與 potion 不同來源的評測腳本**，引用時應一併註明「同表」。
- ⚠️ 模型卡自報分數未經第三方複核（`model-index` 的 `verified` 欄位在 e5-small 為 `false`）。論文引用時應標明「模型卡自報」。

## 五、建議的核心對手與理由

依「實務上真的會部署」與「可對比性」兩個判準，建議核心對手為 **3 個**，另 2 個作上限／下限錨點：

### 核心對手（必做）

1. **`minishlab/M2V_multilingual_output`** — 同架構、同參數量（差 0.14%）、同檔案大小（差 0.14%）、同授權。
   **控制住所有變數，只換老師（bge-m3 → LaBSE）與 Tokenlearn 有無。** 這是整個對照設計裡最乾淨的一組，也是最不容易被老師質疑的一組。

2. **`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`** — 參數量最接近的 Transformer（−8.15%），下載量全表最高（45.67M），有官方 int8 量化。
   **它回答的是實務問題：「同樣 ~0.5 GB 磁碟，Transformer 換到多少品質、付多少延遲？」**
   必須同時報告它的 **128 token 實務上限**，這是我方在長文件場景的結構性優勢。

3. **`intfloat/multilingual-e5-small`** — 與 MiniLM 實質同構（參數量差 512），但 **max_seq_length 是 512 而非 128**。
   與 MiniLM 並列可把「長度」這個變數從「架構」裡拆出來，是很強的實驗設計論證。

### 錨點（必做，但定位為上限／下限而非「同級」）

4. **`BAAI/bge-m3`（上限錨點）** — potion 的直接老師。
   **「學生距離老師多遠」是本研究最核心的一句話**，沒有它就沒有論證。定位必須誠實寫成「上限對照（2.11 GiB）」，不可寫成同級對手。

5. **`minishlab/potion-base-32M`（下限錨點）** — 唯一真正落在 100–200 MB 的模型。
   用途是畫出「參數量 — 品質」曲線的斜率，並誠實展示「100–200 MB 戰場」實際對應到什麼程度的品質（且僅限英文）。

### 可選（若篇幅允許）

6. **`sentence-transformers/LaBSE`** — 雙重身分（M2V 的老師 + potion 卡片的對照列），且是唯一能與 potion 做**同欄位 `Mean (Task)` 直接相減**的模型（52.07 vs 47.31）。
   缺點是 1.75 GiB 且**沒有官方量化版**，實務部署度低於 MiniLM。若只選一個老師級模型，**選 bge-m3**；若能選兩個，LaBSE 提供的是「同欄位可比的絕對差距」，價值不同。

### 建議的評估敘事（一句話）

> 我們在**單機 CPU 可部署**（定義 A）的前提下比較；在**參數量同級**（定義 B）的四個模型中，potion 與 M2V 以靜態查表取得最低延遲，MiniLM 與 e5-small 以 Transformer 換取品質但受 128／512 token 上限約束；bge-m3 與 LaBSE 作為**上限錨點**，用以量化「蒸餾損失」的大小。
